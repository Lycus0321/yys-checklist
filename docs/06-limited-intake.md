# 06 · 限时条目录入规范（`limited.db.json`）

> 对应数据版本：`2026.10.27-限时活动更新` ｜ 事实核对日期：2026-10-27
> 本文回答：**查到新活动之后，一条数据该怎么写进 `limited.db.json`、写完怎么验、哪些坑踩过。**
> 前置：`AGENTS.md` 的红线（尤其第 5、6、7、8 条）｜ 数据模型与规则落点：`02` 第 5、8 节 ｜ 工具链：`03` 第 5、6 节

## 0. 一句话

`limited.db.json` 装**非常驻条目** —— 有起止、到点自动下线、随活动增删的那些。
它是**纯数据**：录入只改这一个 JSON，不改代码；**一次录入宁少勿错**，宁可少一条，不要多一条错的。

## 1. 先判断：这条该进哪个文件

| 条目性质 | 进哪个文件 | `id` 前缀 | `cycle` |
| --- | --- | --- | --- |
| 每期都在、按周期自动翻篇（每日 / 每周 / 每月） | `items.db.json` | `daily_` / `weekly_` / `monthly_` | 对应周期 |
| 有起止、到点归档、随活动增删（限时 / 活动 / 版本） | **`limited.db.json`** | **`ltd_`** | **`limited`** |

⚠️ **最容易判错的一类：活动期内的「每日任务」不属于每日。**
它不按天翻篇，而是"活动期内可做 N 次"——所以周期仍是 `limited`，用**子步骤（`children`）**表示次数，
它只出现在限时页。`拾光永恒` 4 条（各 14 步）就是这么写的。
今日 / 本周 / 本月三页按 `cycle` 取条目，**只列常驻**；"周期是 `daily` 却带 `until`"这一类已不存在。

> 页面归属、重置口径、统计口径一律按 `Item.cycle` 判断，**与文件归属无关**（`api/mock/db.ts` 的注释）。
> 两个文件在 `mergeItems` 之前合并成一份，下游对拆分无感知。

## 2. 字段表

### 2.1 必填

| 字段 | 规格 | 说明 |
| --- | --- | --- |
| `id` | `^[a-z0-9_]+$`，**全库唯一** | 前缀 `ltd_`；**子步骤 id 与条目 id 共用同一个键空间**（勾选态 / 排序 / 隐藏都按 id 索引，撞了就串台） |
| `name` | 2–24 字 | 卡片标题。**不要带 `k/N` 后缀**（按名字猜分组那套已删，后缀只会误导，`db:check` 会警告） |
| `cycle` | 恒 `"limited"` | 枚举四类之一（`daily` / `weekly` / `monthly` / `limited`） |
| `origin` | 恒 `"preset"` | 这两个 JSON 里的条目都是随包发布的预设；用户自建存在本机分片，不写这里 |

### 2.2 常用可选

| 字段 | 规格 | 说明 |
| --- | --- | --- |
| `path` | 建议 ≤40 字 | 入口路径，卡片上的「入口」行：`"活动页 → 拾光永恒"` |
| `gainKind` | 枚举值数组，≤8 项、不重复 | 会掉哪些东西。**浮动收益只标类型、不填数值**（见 3.1） |
| `gain` | `{ jade / blackFrag / blueTicket: 正数 }` | **只写保底固定数值**；写了就必须有 `>0` 的一项 |
| `gainNote` | 建议 ≤40 字 | 固定收益的口径说明（`"每只 20 勾"`）；浮动收益写"不计入固定收益" |
| `condition` | 建议 ≤40 字 | 触发条件（`"需声望 2000"`） |
| `note` | 建议 ≤60 字 | 提醒备注。**只写玩家可见的事实** —— 不写"步数怎么算出来的、改在哪个界面、依据哪篇攻略、谁在什么时候删它"（2026-09-29 清理过一批，见 `CHANGELOG`） |
| `start` | `YYYY-MM-DD` | 活动开始日；到日子才在卡片上提示「开启」 |
| `deadline` | `YYYY-MM-DD[ HH:mm]` | 活动截止：**到点仍要提示去领**，不让条目消失 |
| `until` | `YYYY-MM-DD` | **从清单下线**的日期（见第 4 节） |
| `time` / `timeEnd` | `HH:mm` | 每天几点到几点能玩；`timeEnd` 必须晚于 `time` |
| `timeNote` | 建议 ≤30 字 | 时间窗的补充（"寮自定"这类） |
| `children` | 1–31 项 | N 次任务，**见第 5 节** |

### 2.3 不要出现在这里

| 字段 | 为什么 |
| --- | --- |
| `days` | 星期适用规则，属常驻条目的进阶字段 |
| `autoDaily` | 一键日常的候选标记，只对**常驻每日**有意义 |
| `isAutoHub` | 一键日常入口本身，全库**恰好 1 条**，在 `items.db.json` 里 |
| `premium` | 付费前置标记，当前只在常驻条目上用过 |
| `since` | 语义是"某日起适用"，当前全库无人使用 —— 别新开 |
| `value` / `time2` / `source` / `reward` / `entry` / `action` | **已从数据模型删除**，写进去会被字段白名单拦下 |

## 3. 收益怎么填

### 3.1 只写保底固定值

- **有保底数值** → 写进 `gain`（三币种：`jade` / `blackFrag` / `blueTicket`），并在 `gainKind` 里标出对应类型；
- **数量浮动 / 区间 / 未公布** → **只标 `gainKind`，不写 `gain`**。例如"5 级寮 200 功勋 = 3–5 片"是**区间**，
  写成数值就等于替游戏编了一个保底值；把它写进 `gainNote` 并注明"不计入固定收益"。
- `gain` 三个币种**全为 0** 等于没标固定收益 → 报错；`gain.xxx > 0` 但 `gainKind` 没标对应类型 → 报错
  （黑碎一律标 `blackFrag` —— `blackDaruma` 已于 2026-09-30 并入它，**1 黑蛋 = 25 黑碎**）。

### 3.2 `gainKind` 必须逐条人工核定

**禁止用正则从任何文本字段反推**（`AGENTS.md` 红线第 7 条）。历史教训：曾用正则把「免费黑蛋礼包」
标成黑碎 + 黑蛋 + 达摩 + 碎片，把「地域鬼王 皮肤券」拆成皮肤 + 券（子串重叠误判）。
枚举全集见 `src/domain/enums.ts` 的 `GAIN_KIND`，中文标签在 `meta.db.json` 的 `dicts`。

⚠️ **2026-09-30 起全集只有 9 类**（由 18 类收口，用户逐类判断）：
`jade` 勾玉 / `blueTicket` 蓝票 / `blackFrag` 黑碎 / `skinTicket` 皮肤券 / `medal` 勋章·功勋 /
`soul` 御魂 / `gold` 金币 / `stamina` 体力 / `ssr` SSR/SP。
**已经没有「其他」「达摩」「皮肤外观」「碎片」「兑换材料」这些筐** —— 说不清的不再编码成数据，
所以"这条奖励该标什么"答不上来时，**正确地不标**（`gainKind` 整体留空）比塞一个筐好。
两条折算/合并口径：① 黑蛋并入黑碎，**1 黑蛋 = 25 黑碎**（录入时直接折成黑碎数值）；
② 寮功勋并入勋章（标签「勋章·功勋」）、首领御魂并入御魂。

### 3.3 一天两次 → 拆成两条

`time` 只能表达一个时间窗，所以"上午一次、晚上一次"必须拆成 `xxx_am` / `xxx_pm` **两条**，
且两条 `gain` 之和等于原条目总量。同一件事"要做 N 次"则相反 —— **不要拆条目**，用子步骤（第 5 节）。

## 4. 时间三兄弟与归档行为

| 字段 | 语义 | 落点 |
| --- | --- | --- |
| `start` | 活动开始（未到日子时卡片提示「开启」） | 卡片徽章 |
| `deadline` | 活动截止 —— **仍要提示去领**，不让条目消失 | 限时页排序 + 3 天内临期高亮 |
| `until` | **从清单下线** | `domain/reset.activeItems`（**数据层**过滤，不是渲染层判断） |

- 到了 `until` 那天，条目自动从所有清单消失（勾选与日志照旧保留，只是不再展示）。
- **到期后要清理**：条目还躺在 JSON 里时，`npm run db:check` 会警告 `until=… 已过期，应从清单归档` ——
  确认活动确实结束后，把这条从 `limited.db.json` 删掉。
- 限时页排序：`domain/sort` 的 `deadlineRank` 会**回退读 `until`**；两个都没有的（联动、待定档）一律沉底。
- 既无 `deadline` 也无 `until` 时会警告，**除非** `note` 里显式写了未知，即命中
  `未公布 / 待定 / 以游戏内为准 / 待核` 之一（`tools/build.js` 的 `isExplicitlyPending`）。
- **活动期的「每日任务」同样要填 `deadline`**（填活动本体结束的时刻），`until` 填次日。
  只填 `until` 的话，截止徽章会显示**「截止未定」** —— `domain/countdown.deadlineBadge`
  **只读 `deadline`**、不回退 `until`（它回答的是"活动几点截止"，`until` 是下线日、差一天）；
  而排序的 `domain/sort.deadlineRank` **是**回退读的（它要的是"催促程度"的近似）——
  两处口径不同是有意的，别互相"对齐"。2026-09-29 就补过一批漏填：`拾光永恒` 4 条
  从 `daily` 改判 `limited` 时只填了 `until`，界面上一直显示"截止未定"。

## 5. N 次任务：`children`

### 5.1 什么时候用

同一件事**要做 N 次**：活动期内每天可做一次、每周可兑换多次、一天可刷几把。
清单页上它折叠成**一张卡**（菱形进度格 + `cur/total`），点一下推进一格，整组做完才进「已完成」。

### 5.2 父写什么、子写什么

- **父条目写"每步"的收益，不是总收益** —— 统计按**叶子**算（`tools/build.js` 的 `leaves`）：
  `N 步 × 父 gain`。
  例：`荣誉商店·蓝票` 父 `gain: { blueTicket: 1 }` + 2 步 = 每周 2 张；
  `地域鬼王` 父 20 勾 + 3 步 = 60 勾。**写错这一条会让统计整组翻 N 倍或只剩 1/N。**
- 父条目写**逐次相同**的一切：周期 / 时间 / 入口 / 截止 / 条件 / 备注 / 收益。
- 子步骤只写**逐次可能不同**的那几项，白名单（写了白名单外的字段直接报错）：

  | 子字段 | 用途 |
  | --- | --- |
  | `id` | 必填，全局唯一 |
  | `gain` / `gainKind` / `gainNote` | 这一步的收益与口径（缺省继承父） |
  | `condition` / `note` / `timeNote` | 这一步的条件 / 说明 / 时间备注 |

- 周期 / 时间 / 入口 / `until` / `autoDaily` / `origin` 一律**继承父**，写在子步骤上是无法表达的脏数据。
- 步数上限 **31**（进度格超过 7 格就不再画格子，只留 `cur/total`）。
- 整组同进同出：子步骤不进 `order` / `hidden` / 置顶 / 排序 / 筛选，也不单独参与编辑改写。

### 5.3 最小写法

```jsonc
{
  "id": "ltd_xxx_yyy_1",   // 子 id 与条目 id 共用键空间，必须全局唯一
  "note": "第二次要在 9/30 前做完"   // 逐次不同时才写
}
```

## 6. 录入步骤

```text
1. 判断归属（第 1 节）→ 定 id 前缀与 cycle
2. 写草稿（可先落到 tools/templates/new-items.draft.json，改完再合并）
3. npm run db:check        → 0 错误；警告逐条看（过期未归档、缺 until、k/N 后缀都会在这里现形）
4. npm run db:calibrate    → 导出待核清单（收益 / 截止日 / 时间窗）
5. 人工核对：优先官方公告与游戏内截图，AI 水文站不采信
6. 落 src/db/limited.db.json；数据版本号与 meta 按发版流程处理（AGENTS.md 红线第 8 条）
7. 在 CHANGELOG.md 的「数据」组记一条（写清增删改了什么、db:check 的输出）
```

## 7. 校验速查：哪些是工具强制的

`npm run db:check`（`tools/build.js`）**会拦下来（error）**的：

- 字段白名单之外的键、缺 `id` / `name` / `cycle` / `origin`；
- `id` 格式非法或重复（**含子 id 与条目 id 互撞**）；`name` 不在 2–24 字；
- `cycle` / `gainKind` / `origin` 不在枚举内；`gainKind` 超 8 项或有重复；
- `gain` 出现未知币种、负值、三项全 0，或 `gain > 0` 却没标对应 `gainKind`；
- 日期 / 时刻格式不对、`deadline < start`、`timeEnd <= time`、`since > until`；
- `children` 是空数组、超 31 项、子字段越界、子 id 重复或格式非法。

**只会警告（warn）**的：`until` / `deadline` 已过期、限时项既无 deadline 也无 until 且未标"待定"、
`name` 残留 `k/N` 后缀、标了 `isGuildTime` 却没填 `time`。

**工具不查、只能靠本规范守住的**（约定）：

- `limited.db.json` 里的条目 `cycle` 必须都是 `limited`、id 前缀用 `ltd_`（错放不会报错，但页面归属会乱）；
- `gainNote` ≤40 / `condition` ≤40 / `note` ≤60 / `timeNote` ≤30 字（`children` 的子字段则**会**被查）；
- `note` 只写玩家可见的事实、不写维护口径；
- 父条目的 `gain` 写"每步"而不是总量。

## 8. 踩过的坑（照着避开）

1. **父 `gain` 写成总量** —— 统计按叶子算，N 步就会翻 N 倍（见 5.2）。
2. **子步骤里写 `cycle` / `time` / `until`** —— 直接报错；一张卡只有一个周期。
3. **子 id 用父 id 加序号之外的东西** —— 保持 `父id_1` / `_2` 的写法最不容易撞。
4. **`gain` 三项全 0** —— 等于"标了固定收益却没有任何数值"；浮动就只标 `gainKind`。
5. **区间值写成定值**（"3–5 片"写成 3 或 5）—— 那是替游戏编保底，写进 `gainNote` 说明即可。
6. **名字里留 `k/N`** —— 分组关系已写进 `children`，后缀只会让人以为还有另一套机制。
7. **`note` 写维护口径** —— "子步骤 = 剩余可做次数（…可在「条目管理」里改）"这类话 2026-09-29 已整批清理。
8. **已删字段复活** —— `value` / `time2` / `source` / `reward` / `entry` / `action` 都不要写回来。
9. **拿正则从文本反推 `gainKind`** —— 一律逐条人工核定（红线第 7 条）。

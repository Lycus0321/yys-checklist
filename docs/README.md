## 时效与更新约定

1. **锚点是符号名，不是行号。** 文档里引用真实路径与符号名（函数 / store / 常量），行号会随改动漂移，所以只在必要时给出。定位时优先搜符号名。
2. **规模数字要重跑确认。** 文档中的条目数、御魂数、测试用例数等来自核查时的实测；改数据后请重跑 `npm run db:check` 与 `npm test` 再更新文档里的数字。
3. **改了这些，要同步改文档**：

| 改动 | 需要同步的文档位置 |
| --- | --- |
| 条目字段规格 / 枚举 | `02` 第 4、5 节，`03` 第 7 节 |
| 契约新增或删除方法 | `02` 第 1 节，`01` 第 7 节（数据流） |
| 新增 store / 页面 / domain 模块 | `01` 第 2、6、8 节，`02` 第 6 节 |
| 新增目录或改变目录职责 | `01` 第 2 节 |
| 完成路线图中的未完成项 | `04` 第 4 节，必要时更新 `AGENTS.md` 的红线 |
| 新增强制约定（lint 规则、口径纪律） | `AGENTS.md` 红线 + `03` 第 1、2 节 |
| 任何用户可见或结构性改动 | 根目录 `CHANGELOG.md` 的 `[Unreleased]` 区（约定见 `AGENTS.md` 红线第 8 条） |

4. 文档不复制数据明细（例如 103 条条目逐条内容、70 种御魂清单）—— 明细以 `src/db/*.db.json` 为唯一真值，避免双份维护。
